# Демо-версия WMS для презентации

Демо — это та же программа, но с **отдельной базой** (`instance/demo.db`) и
**вымышленными данными**: склады, товары, приемки, перемещения, план
отгрузок Ozon/WB, выработка швей. Боевая база `instance/wms.db` не
затрагивается; в интерфейсе сверху висит жёлтая плашка «ДЕМО-ВЕРСИЯ».

## Запуск

На любом компьютере с установленными зависимостями (`pip install -r requirements.txt`):

```
python3 run_demo.py            # http://localhost:5050
python3 run_demo.py --reset    # стереть демо-базу и наполнить заново (перед показом)
python3 run_demo.py --lan      # открыть в локальной сети (показать с телефона)
python3 run_demo.py --port 8080
```

На сервере с `.venv` (как у боевой системы) — тем же интерпретатором:

```
cd /opt/wms && .venv/bin/python3 run_demo.py --reset
```

Демо слушает порт 5050 и не мешает боевому приложению (оно на 8000 за nginx).
Выгрузка в Google Таблицу в демо отключена, 1С не используется — случайно
отправить вымышленные данные наружу нельзя.

Показать демо по постоянной ссылке (по желанию): подготовить базу и запустить
gunicorn с теми же переменными, что ставит `run_demo.py`:

```
.venv/bin/python3 run_demo.py --seed-only
WMS_DEMO=1 WMS_DATABASE_URL=sqlite:////opt/wms/instance/demo.db \
WMS_GOOGLE_CREDENTIALS_FILE=/nonexistent .venv/bin/gunicorn --bind 127.0.0.1:8001 wsgi:app
```

## Входы (пароль у всех — `demo`)

| Логин | Роль | Что видит |
|---|---|---|
| `admin` | Администратор | всё |
| `kladovshik` | Кладовщик | приемка, размещение, перемещения |
| `logist` | Логист | только передача отгрузок транспорту |
| `shveya1` (`shveya2`, `shveya3`) | Производство | только сканирование изделий |
| `fulfilment` | Фулфилмент (Склад №3) | только свои приемки и перемещения |

## Что в базе

- 3 склада (Основной, Склад №2, Склад №3) с рядами и ячейками, ~90 коробов
  с остатками, неразмещённый остаток «на разбраковке».
- 18 товаров (шапки, кардиганы, свитеры, шарфы) с видами и нормами времени;
  у одного товара есть доп. штрихкод `46999000000001`.
- Приёмки: завершённая, на разбраковке, черновик.
- 14 перемещений: часть уже принята, часть «в пути», две принятые **с
  недовозом**, один черновик.
- План отгрузок Ozon (6 городов) и WB (5 городов) с датами плана по городам.
  Ozon «успевает» в срок, WB — «не успевает»: на экране видны оба состояния.
- Выработка трёх швей за последние дни — отчёт «Эффективность».

Раздел «МВБ Логистика» в демо не наполнялся.

## Сценарий показа (≈10 минут)

1. **План отгрузок** (`admin`) — сводка, карточки Ozon/WB: план, в пути, % и
   прогноз «успеваем / не успеваем». В таблице городов поменять «Дату плана» —
   строка пересчитается без перезагрузки страницы и встанет по порядку дат;
   под датой — факт к этой дате в штуках и %.
2. **Перемещение** — список документов с цветными статусами (сборка → заявка
   на МП → отгрузка → приёмка), открыть документ: короба, печать стикеров и
   накладных. Показать принятое с недовозом — расхождение видно бейджем.
3. **Номенклатура и остатки** — остатки по трём складам, «Где товар», поиск
   по основному и доп. штрихкоду.
4. **Приёмка** — накладная на разбраковке, как выделяется брак.
5. **Производство** → «Эффективность» (`shveya1` сканирует изделие, `admin` —
   отчёт по сотрудникам).
6. **Роли** — зайти под `logist` и `fulfilment`: каждый видит только свой
   кусок системы.

Перед важным показом: `python3 run_demo.py --reset` — свежая база, даты в плане
и перемещениях пересчитываются от сегодняшнего дня.
