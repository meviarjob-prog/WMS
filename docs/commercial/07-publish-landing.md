# Этап 7. Публикация лендинга на своём домене

Лендинг — статичная папка `landing/` (HTML, три картинки, `robots.txt`).
Серверная часть не нужна, поэтому публиковать его проще и безопаснее на
**отдельном** хостинге, а не на сервере с боевой WMS.

## Почему не на сервере с боевой WMS

Рядом с лендингом окажется ваша рабочая система: один IP-адрес, сертификаты и
записи DNS позволяют связать сайт с вашей компанией. Если вам важно, чтобы
витрина не вела к вашему производству, держите её отдельно.

## Шаг 1. Домен

1. В кабинете регистратора включите **скрытие данных владельца** (WHOIS-privacy).
   Для физлиц зона .ru скрывает данные по умолчанию; для других зон опция
   часто платная или включается галочкой. Проверьте результат запросом WHOIS.
2. Заведите отдельную почту для проекта (на домене или отдельный адрес), чтобы
   не светить личную.
3. Рекомендую подключить DNS домена к **Cloudflare** (бесплатный тариф): быстрее
   меняется, есть защита и бесплатный HTTPS. Для этого в кабинете
   регистратора замените NS-серверы на те, что выдаст Cloudflare.

## Шаг 2. Хостинг для статики (любой из вариантов)

| Вариант | Как | Подходит, если |
|---|---|---|
| **Cloudflare Pages, прямая загрузка** | Pages → Create → Direct Upload → загрузить папку `landing/`; привязать свой домен | хотите бесплатно и без связки с GitHub-аккаунтом (репозиторий подключать не нужно) |
| Свой маленький VPS с nginx | положить файлы в `/var/www/landing`, настроить сайт и сертификат (`certbot --nginx`) | нужен контроль и вы готовы поддерживать сервер |
| Хостинг-провайдер со статикой (Beget, Timeweb и т. п.) | залить файлы по FTP/через панель | привычный путь, оплата в рублях |

Если выбираете VPS (отдельный облачный сервер, не тот, где боевая WMS), всё
делает скрипт `deploy/landing_setup.sh`: ставит nginx, настраивает сайт и
получает бесплатный HTTPS-сертификат. Порядок:

1. В DNS домена создайте A-запись на IP нового сервера (и `www`, если нужен).
2. С компьютера: `scp -r landing/* root@IP_СЕРВЕРА:/var/www/landing/`
   (если папки нет — сначала `mkdir -p /var/www/landing` на сервере).
3. На сервере: `bash landing_setup.sh ваш-домен.ru you@example.com`
   (с www: `WWW=1 bash landing_setup.sh ваш-домен.ru you@example.com`).

Обновить сайт позже — просто повторить `scp`, перезапуск не нужен.

Если настраиваете nginx вручную, минимальный конфиг:

```
server {
    listen 80;
    server_name ваш-домен.ru www.ваш-домен.ru;
    root /var/www/landing;
    index index.html;
    location / { try_files $uri $uri/ =404; }
}
```

После этого `certbot --nginx -d ваш-домен.ru -d www.ваш-домен.ru`.

## Шаг 3. Перед загрузкой — подставить свои данные

Откройте `landing/index.html` и найдите жёлтые места (`class="todo"`):
- реквизиты в подвале (ИП или ООО, ИНН);
- в блоке «Запросить демо или пилот» замените `ВАШ_TELEGRAM` и `ВАШ_EMAIL`;
- цену в разделе «Сколько стоит?» (после расчёта по `05-pricing.md`).
Затем уберите жёлтую плашку «Подставьте свои контакты…».

Если не готовы указывать реквизиты публично, оставьте только контакты, но
учтите: при заключении договора реквизиты всё равно понадобятся, а
коммерческий сайт организации обычно содержит сведения о продавце.

## Шаг 4. Проверка после публикации

- Открыть с телефона и с компьютера, пройти по обеим кнопкам контактов.
- Убедиться, что картинки загружаются, а сайт открывается по `https://`.
- Проверить, что в тексте и на скриншотах нет реальных названий (склад,
  компания, адреса) — демо-данные вымышленные, но перепроверьте глазами.
- Добавить сайт в Яндекс.Вебмастер и Google Search Console, чтобы он попал в
  поиск (понадобится подтверждение владения — через файл или запись DNS).

## Шаг 5. Что добавлять дальше

1. **Метрика посещаемости** (например, Яндекс.Метрика): при подключении
   потребуется уведомление о cookie/политика обработки данных — решите это
   до включения счётчика. Пока сайт без счётчиков и без форм, он ничего не
   собирает.
2. **Живое демо** на поддомене `demo.ваш-домен.ru`: запуск `run_demo.py` на
   отдельном маленьком сервере за nginx, ежедневный сброс по cron
   (`python3 run_demo.py --reset`). Публичное демо с паролем `demo` означает,
   что в него может зайти любой: данные вымышленные, но ставьте его на
   **отдельный** сервер и ограничьте ресурсы.
3. **Страница политики конфиденциальности и оферта**, когда появятся форма
   заявки или оплата (проверьте у юриста).
4. **Кейс и видео** на лендинге (`01-case-study.md`, `03-video-script.md`).

## Что делать сразу после публикации

Запустить этапы 2 и 4: личные сообщения 30 знакомым и партнёрам 1С со ссылкой
на сайт и видео, цель — 5 демо за первые две недели (`02-pilots.md`,
`04-channels.md`).

## Если сайт медленно открывается

1. **Вес страницы.** Лендинг должен весить около 150 КБ целиком (HTML и три
   картинки в WebP). Не добавляйте тяжёлые картинки и внешние шрифты/скрипты.
2. **Сеть до Cloudflare.** Часть российских провайдеров нестабильно работает
   с зарубежными хостингами и CDN, из-за чего страницы грузятся долго или
   картинки не догружаются. Проверьте: откройте сайт по мобильной сети и по
   Wi-Fi, а также через VPN. Если с VPN заметно быстрее, причина в сети, а не
   в сайте.
3. **Что делать.** Разместить статику у российского провайдера (хостинг или
   облако в РФ, например у регистратора домена) и оставить DNS там же либо в
   Cloudflare без проксирования (серое облако). Файлы те же: загрузить
   содержимое `landing/` в папку сайта.
4. **Первая загрузка после смены NS** бывает медленнее из-за прогрева DNS и
   выпуска сертификата; повторная проверка через несколько часов.
