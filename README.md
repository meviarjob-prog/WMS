# WMS — система управления складом

Веб-приложение на Python (Flask + SQLite) для складского учета: приемка товара
(количество), размещение в короба и по ячейкам отдельной операцией,
перемещение коробов между складами, печать термоэтикеток 58×40 мм, загрузка
номенклатуры и выгрузка отчетов в Excel.

## Возможности

- **Номенклатура**: список, добавление вручную, скачивание Excel-шаблона,
  импорт/обновление номенклатуры из заполненного шаблона, экспорт в Excel.
- **Склады, зоны и ячейки**: код склада присваивается автоматически
  (WH-001, WH-002, ...). Внутри склада — зоны (стеллаж/участок, объединяет
  несколько ячеек, печатается крупной A4-этикеткой) и ячейки хранения,
  каждая ячейка может быть привязана к зоне. У каждой ячейки есть страница
  с текущим списком коробов, которые в ней лежат.
- **Приемка товара**: создание документа приемки → добавление позиций
  сканером штрихкода (добавляется сразу, без нажатия Enter — короткая пауза
  после скана сама срабатывает как подтверждение) или ручным поиском "по
  вхождению" → количество уже добавленной позиции можно поправить прямо в
  списке → завершение. Приемка — это только количество товара по складу в
  целом; упаковка в короба и расстановка по ячейкам в нее не входит и
  выполняется отдельно, операцией «Размещение».
- **Размещение товара**: отдельная операция, не привязанная к конкретной
  приемке — показывает общий неразмещенный остаток принятого товара по
  складу (двойной клик по строке остатка сразу берет всё доступное
  количество под упаковку), позволяет упаковать его в короба (номер короба
  генерируется автоматически, печать этикетки товара и короба) и
  расставить короба по ячейкам (сканом/вводом кода ячейки, печать этикетки
  ячейки). Здесь же можно доразместить в ячейку уже упакованные короба,
  которые приехали перемещением без ячейки. Выгружается в Excel.
- **Перемещение**: список коробов, едущих с одного выбранного склада-отправителя
  на один выбранный склад назначения (оба указываются при создании списка).
  Короба сканируются один за другим и добавляются в список — весь товар
  внутри каждого короба переезжает вместе с ним (можно посмотреть состав
  короба прямо со страницы списка); при сканировании короба, которого нет
  на указанном складе-отправителе, будет ошибка. Для каждого короба сразу
  можно указать ячейку на складе назначения (или оставить пустой и
  доразместить позже через «Размещение»). Журнал перемещений выгружается в
  Excel.
- **Карточка короба**: у каждого короба есть страница с его текущим
  расположением (склад/ячейка) и полным списком товаров внутри — доступна
  со страницы ячейки, из «Размещения» и «Перемещения».
- **Печать этикеток 58×40 мм**: для товара — штрихкод + наименование; для
  короба — генерируемый номер короба в виде штрихкода; для ячейки — код ячейки
  в виде штрихкода. Каждая этикетка доступна как HTML-страница для печати из
  браузера (авто-открытие диалога печати) и как готовый PDF нужного размера.
  Для зоны — отдельная крупная **A4-этикетка** (штрихкод, код/название зоны,
  список входящих ячеек) для навешивания на стеллаж/вход в зону.
- **Отчеты**: выгрузка приемки, размещения и перемещений в Excel с фильтром
  по складу и периоду.
- **Поиск товара**: по штрихкоду (сканер эмулирует клавиатуру; добавляется
  сразу, Enter не обязателен) и вручную — поле с автокомплитом, поиск по
  вхождению в артикул/наименование/штрихкод.
- **Мобильная версия**: интерфейс адаптивный (открывается с телефона как
  обычный сайт), плюс сканирование штрихкода прямо камерой телефона (кнопка
  📷 у полей приемки/размещения/перемещения — свой сканер не нужен) и
  установка значка на экран телефона (PWA), см. раздел ниже.
- **Несколько пользователей**: вход по логину/паролю, у каждого пользователя
  свой аккаунт (админ создает их в разделе «Пользователи»), в каждом
  документе приемки/размещения/перемещения видно, кто его создал. Несколько
  человек могут одновременно работать с телефонов и с разных компьютеров —
  сервер настроен на конкурентный доступ (WAL-режим SQLite, многопоточность).

## Установка и запуск

```bash
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python run.py
```

Приложение будет доступно на `http://localhost:5000`. База данных SQLite
создается автоматически в `instance/wms.db` при первом запуске.

## Первый вход и пользователи

При самом первом запуске автоматически создается пользователь-администратор
с логином `admin` и случайным паролем — он один раз печатается в консоли,
где запущен `python run.py`:

```
Создан первый пользователь администратора:
  Логин:  admin
  Пароль: <случайный пароль>
```

Сохраните этот пароль (или сразу смените после входа — меню с именем
пользователя вверху справа → «Сменить пароль»). Дальше зайдите под ним и
создайте остальных сотрудников в разделе **Пользователи** (виден только
администраторам) — для каждого генерируется свой временный пароль, который
нужно передать сотруднику. Каждый может сменить временный пароль на свой
после первого входа.

## Печать этикеток на термопринтере 58×40 мм

Для каждой этикетки (товар / короб / ячейка) есть:

1. **HTML-страница печати** — открывается по кнопке "🖨 Этикетка", размер
   страницы задан точно 58×40 мм (`@page { size: 58mm 40mm; margin: 0; }`).
   При открытии автоматически вызывается диалог печати браузера — выберите
   термопринтер и печатайте без полей/масштабирования ("Actual size").
2. **PDF того же размера** (`.pdf`-версия каждой этикетки) — для случаев,
   когда удобнее отправить готовый PDF-файл напрямую в очередь печати
   термопринтера.

При упаковке короба доступна массовая печать этикеток всех товаров, которые
в него уложены (кнопка "Этикетки товаров" на карточке короба).

## Работа с телефона: сканирование камерой и установка на экран

Приложение открывается с телефона как обычный сайт (адаптивная верстка), и
дополнительно умеет сканировать штрихкод камерой телефона прямо в браузере —
без Bluetooth/USB-сканера — и устанавливаться на домашний экран как
приложение (PWA).

### Как открыть с телефона

1. Компьютер и телефон должны быть в одной Wi-Fi сети.
2. При запуске `python run.py` в консоли будет выведен адрес вида
   `http://192.168.х.х:5000` — его нужно открыть в браузере на телефоне.
3. Если Windows спросит про доступ по сети для Python — разрешить
   (иначе телефон не достучится до сервера через файрвол).

### Сканирование камерой (требует HTTPS)

Браузеры разрешают доступ к камере только по защищенному соединению
(HTTPS) — обычный `http://` с телефона камеру не откроет (это ограничение
самого браузера, не приложения). Чтобы включить HTTPS с самоподписанным
сертификатом для локальной сети:

```bash
# Linux/macOS:
WMS_HTTPS=1 python run.py

# Windows PowerShell:
$env:WMS_HTTPS="1"; python run.py
```

После этого на телефоне открывайте `https://<адрес>:5000` — браузер один
раз покажет предупреждение о небезопасном сертификате (это нормально для
самоподписанного сертификата в локальной сети), нужно нажать
"Дополнительно" → "Все равно перейти". Дальше кнопка 📷 рядом с полями
сканирования (приемка, перемещение) откроет камеру и после наведения на
штрихкод автоматически подставит значение в поле — как будто оно
отсканировано обычным сканером.

Без HTTPS кнопка 📷 покажет понятное сообщение об ошибке, но обычный ручной
ввод/поиск и подключенный физический сканер штрихкода (эмулирующий
клавиатуру) продолжают работать как обычно.

### Установка значка на экран телефона

- **Android (Chrome)**: меню (⋮) → "Добавить на главный экран" /
  "Установить приложение".
- **iPhone (Safari)**: кнопка "Поделиться" → "На экран «Домой»".

После этого WMS откроется отдельным окном без адресной строки браузера — как
обычное приложение.

## Готовый .exe для Windows (сервер + ссылка с камерой в одном файле)

Самый простой способ раздать программу коллегам — собрать её в один файл
`WMS.exe`. Двойной клик по нему запускает сервер и сразу выводит в консоли
защищённую HTTPS-ссылку (через Cloudflare Tunnel), которая работает из
любой сети и с камеры на телефоне — без установки Python, без настройки
сервера и без покупки домена.

Как собрать `WMS.exe` (делается один раз, на Windows) — подробная
пошаговая инструкция: [`deploy/build_exe.md`](deploy/build_exe.md).

Готовый `WMS.exe` можно скопировать на любой Windows-компьютер и просто
запускать — данные (база товаров, документы) хранятся в папке `instance`
рядом с `.exe` и сохраняются между перезапусками. Ссылка для доступа
меняется при каждом запуске программы — актуальную нужно раздавать заново.

## Доступ из любой точки — свой сервер (альтернатива .exe)

Всё, что описано выше, работает только пока компьютер с `python run.py` и
телефон/другой ПК находятся в одной сети (Wi-Fi/локальная сеть). Если люди
работают из разных мест — разных офисов, из дома, с мобильного интернета —
нужен собственный сервер, работающий постоянно и доступный из интернета.

### Что понадобится

- Недорогой облачный сервер (VPS) с Ubuntu — от ≈150–300 ₽/мес. Подойдёт
  любой провайдер, например **Timeweb Cloud** (timeweb.cloud) — простой
  русскоязычный интерфейс, принимает российские карты. Альтернативы:
  Selectel, Beget Cloud, reg.ru. При заказе выберите:
  - ОС: **Ubuntu 22.04** или **24.04**
  - Минимальная конфигурация (1 CPU / 1–2 ГБ RAM) — для небольшой команды
    более чем достаточно.
- Свой домен не нужен — адрес вида `https://<IP-сервера>.sslip.io`
  получится автоматически, с настоящим (не самоподписанным) HTTPS-сертификатом,
  без предупреждений браузера — камера на телефоне тоже будет работать без
  дополнительной настройки.

### Установка — одна команда

1. После заказа сервера провайдер пришлёт **IP-адрес** и **пароль root**
   (или вы укажете свой SSH-ключ при заказе).
2. Подключитесь к серверу по SSH. В Windows это делается прямо из
   PowerShell (SSH-клиент встроен, ничего ставить не надо):
   ```powershell
   ssh root@ВАШ_IP_АДРЕС
   ```
   При первом подключении спросит про "fingerprint" — введите `yes`. Затем
   введите пароль root (при вводе пароля символы не отображаются — это
   нормально, просто вводите и жмите Enter).
3. Внутри сервера выполните одну команду (замените e-mail на свой — он
   нужен только для уведомлений об истечении сертификата, необязателен):
   ```bash
   curl -fsSL https://raw.githubusercontent.com/meviarjob-prog/wms/claude/wms-system-python-t1db0u/deploy/setup.sh | bash -s -- you@example.com
   ```
   Скрипт сам поставит всё необходимое (nginx, Python-зависимости, systemd,
   HTTPS-сертификат) — это займёт пару минут. В конце он выведет:
   ```
   Готово! WMS доступен по адресу:
     https://XXX-XXX-XXX-XXX.sslip.io

   Пароль администратора: ...
   ```
   Откройте эту ссылку на любом устройстве (компьютере, телефоне) в любой
   сети — сайт будет доступен отовсюду, не только из офиса.

### Как обновить сервер, когда выходит новая версия

Подключитесь по SSH тем же способом и выполните ту же команду ещё раз —
скрипт безопасно перезапускать: он подтянет свежий код и перезапустит
сервис, ничего не удаляя.

### Резервное копирование

Вся база данных — один файл `/opt/wms/instance/wms.db` на сервере. Стоит
периодически скачивать его копию себе на компьютер (например, раз в
неделю), особенно перед обновлениями:
```powershell
scp root@ВАШ_IP_АДРЕС:/opt/wms/instance/wms.db wms-backup-2026-01-01.db
```

## Типовой сценарий работы

1. **Склады, зоны и ячейки**: создайте склад (код присвоится автоматически),
   при желании — зоны, и ячейки хранения (`Склады и ячейки`).
2. **Номенклатура**: скачайте Excel-шаблон, заполните артикул/штрихкод/
   наименование/ед. изм., загрузите файл через `Импорт из Excel` (или
   добавляйте товары вручную).
3. **Приемка**: создайте документ приемки, добавьте позиции сканером
   (добавляется сразу) или поиском (только количество), завершите — товар
   зачислится в неразмещенный остаток склада.
4. **Размещение**: отдельным шагом (когда удобно, необязательно сразу же)
   создайте документ размещения на этот склад, возьмите нужное количество
   под упаковку (двойной клик по строке остатка — сразу всё доступное
   количество), создайте короб(а) (номер — автоматически), упакуйте,
   распечатайте этикетки, разместите короба по ячейкам (со сканом/вводом
   кода ячейки и печатью этикетки ячейки), завершите.
5. **Перемещение**: создайте список перемещения, укажите склад назначения,
   сканируйте короба один за другим — каждый добавляется в список со всем
   своим содержимым; для каждого короба сразу укажите ячейку на складе
   назначения (или оставьте пустой), завершите — короба переедут разом.
   Короб без ячейки можно доразместить позже через «Размещение».
6. **Отчеты**: выгрузите операции приемки, размещения и перемещения в Excel
   с нужными фильтрами.

## Структура проекта

```
wms/
  models.py               модели БД (пользователи, склады, зоны, ячейки, номенклатура,
                           неразмещенный остаток, короба, документы приемки/размещения/перемещения)
  blueprints/              маршруты Flask по разделам
    auth.py                  вход/выход, пользователи, смена пароля
    main.py                 дашборд
    warehouses.py            склады, зоны и ячейки
    nomenclature.py          номенклатура, шаблон/импорт/экспорт Excel
    receiving.py             приемка товара (количество)
    placement.py             размещение (упаковка в короба + расстановка по ячейкам)
    movement.py               перемещение (список коробов со склада-отправителя на склад назначения)
    boxes.py                    карточка короба (расположение + состав)
    labels.py                 печать этикеток (HTML + PDF, вкл. A4 для зон)
    reports.py                 отчеты (выгрузка в Excel)
    api.py                      поиск (автокомплит, штрихкод)
  utils/
    numbering.py             генерация номеров документов/коробов (атомарно, для конкурентного доступа)
    barcodes.py                генерация PNG-штрихкодов (Code128)
    labels_pdf.py               генерация PDF-этикеток 58×40 мм и A4
    excel_io.py                 шаблон/импорт/экспорт Excel
    http.py                     безопасный Content-Disposition для не-ASCII имен файлов
  templates/, static/        HTML-шаблоны и статика (Bootstrap 5, автокомплит,
                              сканер камеры html5-qrcode, PWA-манифест и иконки)
wsgi.py                    точка входа для gunicorn (продакшн-сервер, см. deploy/)
run.py                      точка входа для локальной разработки (dev-сервер Flask)
deploy/
  setup.sh                    разворачивает WMS на чистом Ubuntu-сервере в одну команду
  requirements-server.txt      доп. зависимости только для сервера (gunicorn)
```

## Технологии

Flask, Flask-Login (авторизация), Flask-SQLAlchemy, SQLite (WAL-режим для
конкурентного доступа), openpyxl (Excel), python-barcode + Pillow
(штрихкоды), reportlab (PDF-этикетки), Bootstrap 5 (интерфейс), html5-qrcode
(сканирование камерой). Внешние JS/CSS-библиотеки хранятся локально в
`static/vendor/` — интернет для работы приложения не нужен (кроме HTTPS-варианта
запуска, который не требует интернета, а только сертификат, генерируемый на лету).
На сервере (см. «Доступ из любой точки») — gunicorn + nginx + Let's Encrypt
вместо dev-сервера Flask.
