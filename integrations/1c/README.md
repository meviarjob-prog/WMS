# Обмен WMS ↔ 1С:УНФ

WMS хранит документы «Перемещение», «Инвентаризация» и «Возврат поставщику»
(из разбраковки приемки). Эта интеграция переносит их в 1С:УНФ по кнопке
«Синхронизировать» во внешней обработке — без изменения самой конфигурации
1С.

## Что и когда выгружается

- **Перемещение** — сразу как завершено в WMS (`Завершить перемещение`), не
  дожидаясь «Принято на складе» на складе назначения: в 1С документ
  «Перемещение товаров» как раз и отражает, что товар в пути, а отдельный
  документ по факту приемки на складе назначения бухгалтерия заводит в 1С
  вручную. Перемещения, которые бухгалтер уже вручную отметил галочкой
  «внесено в 1С» (кнопка на странице перемещения, независима от этого
  API), не выгружаются — считается, что он ведет их отдельно.
  - Склад назначения (`to_warehouse`) для склада-города маркетплейса (те
    WMS создает сама при загрузке плана отгрузок, например «ОЗОН: Казань»)
    подставляется по настройке администратора — страница **«Настройки»**
    → «Склады выгрузки в 1С», отдельное поле на КАЖДЫЙ склад-город (не на
    город целиком): одна и та же площадка одного города может ехать на
    разные склады 1С в зависимости от маркетплейса — например, «ВБ:
    Краснодар» на склад-сортировочный центр, а «ОЗОН: Краснодар» на склад
    фулфилмента, хотя город один и тот же. При этом несколько РАЗНЫХ
    городов WMS могут указывать на один и тот же склад 1С — например
    «Черкесск» и «Пятигорск» оба по умолчанию идут на «Товары в пути ФФ
    ЧЕРКЕССК (Лейла)». Для складов-городов, для которых администратор еще
    не настроил соответствие, подставляется общий запасной склад
    **«Товары в пути на Фулфилмент»**.
    Каждый документ перемещения при этом выгружается сам по себе, как и
    раньше — эта настройка меняет только то, какое имя склада-получателя
    в него подставляется, без объединения документов между собой.
    Исключение — перемещения напрямую между «Основной склад» и «Склад №2
    (Шоссейная 167)»: там всегда передается настоящее название склада
    назначения, эта настройка их не касается.
  - Настоящий склад-получатель WMS (например, «ОЗОН: Казань») в любом
    случае виден в поле `comment` — см. пример ниже.
- **Инвентаризация** — как только завершена в WMS.
- **Возврат поставщику** — из приемки в WMS (приемка проходит этапы
  «Пересчет» → «Разбраковка» → «Завершить приемку»), два источника по
  каждой позиции:
  - **Брак** — на разбраковке указывается кол-во брака.
  - **Недостача** — если на пересчете фактическое кол-во оказалось меньше,
    чем заявлено в накладной (`expected_qty`), разница уходит отдельным
    возвратом с тем же смыслом, что и брак — поставщик недопоставил товар.
    Если на пересчете, наоборот, нашли больше, чем заявлено — возврат не
    создается.

  Выгружается, только если у возврата есть `invoice_number` — то есть
  приемка была загружена из файла накладной (недостача в принципе
  невозможна для строк, добавленных в приемку вручную — сравнивать не с
  чем). Если разбраковку/пересчет сделали на приемке, созданной в WMS
  вручную (номер — внутренний, не настоящая накладная), такой возврат
  никогда не попадет в `export` — заводится в 1С вручную. Все возвраты по
  одной приемке (и брак, и недостача, по всем позициям) объединяются в
  **один** документ 1С с несколькими строками — `id` в ответе это id
  приемки в WMS, а не отдельной строки возврата.
  - Основанием для возврата в 1С:УНФ служит **«Заказ поставщику»**, а не
    сама накладная — 1С ищет его по `order_number` (поле «№ заявки» в
    WMS, вносится вручную при загрузке накладной, т.к. в самом файле
    накладной этого номера нет). Поиск сначала пробует точное совпадение
    с реквизитом «Номер» заказа (например «ШМ-005») — этого достаточно
    само по себе. Если точного совпадения нет — пробует сравнить только
    цифры без ведущих нулей и буквенного префикса (`5` вместо «ШМ-005»),
    но **только вместе с проверкой поставщика** (`supplier`/`supplier_inn`
    в payload): префикс в номере часто кодирует площадку/канал (например
    «ВБ-к04» и «ОЗ-к04» — у обоих голая цифра «4»), и без сверки поставщика
    можно случайно привязать возврат к чужому заказу. Короткий номер без
    точного совпадения по «Номер» найдется, только если у WMS известен
    поставщик приемки и он совпадает с поставщиком найденного заказа — по
    ИНН (надежно, см. ниже) либо, если ИНН нет, нестрого по названию (без
    учета регистра и организационно-правовой формы) — см.
    `НайтиЗаказПоставщикуПоНомеру`/`ТолькоЦифрыБезВедущихНулей`/
    `ИННСовпадает`/`НазванияПоставщикаСовпадают`.
  - **Поиск контрагента-поставщика в 1С — сначала по ИНН, затем по имени.**
    `supplier_inn` в payload заполняется из справочника поставщиков WMS
    (сохраняется автоматически при загрузке накладной). Это основной,
    надежный способ найти контрагента: поле «Наименование» в справочнике
    контрагентов 1С часто внутренний короткий алиас, никак не совпадающий
    с тем, что напечатано в самой накладной (например, в 1С контрагент
    называется «Бедин Денис» без указания формы, а в накладной — «ИП Бедин
    Денис Ильич») — текстовый поиск в таком случае ничего не найдет, даже
    если контрагент в базе есть. Поиск по ИНН (`НайтиКонтрагентаПоИНН`)
    делается первым и, если он не дал результата (в справочнике нет
    контрагента с таким ИНН, у справочника вовсе нет реквизита «ИНН», или
    `supplier_inn` пуст — например, у поставщика в WMS не заполнен ИНН),
    используется старый поиск по названию (`НайтиКонтрагентаПоИмени`) как
    запасной вариант. То же самое и для сверки поставщика при поиске
    заказа по «голым» цифрам выше.
- Документ, который 1С уже забрала и подтвердила (см. ниже), повторно не
  отдается — можно жать «Синхронизировать» сколько угодно раз, дублей не
  будет.
- Создаваемые в 1С документы **не проводятся** — только заполняются и
  сохраняются как черновик, чтобы бухгалтер/кладовщик проверил их перед
  проведением.
- Номер документа WMS передается в поле «Комментарий» создаваемого
  документа 1С — по нему легко найти исходный документ.

## Протокол

Токен доступа генерируется администратором в WMS: **Обмен с 1С** в меню
(только для админа) → «Сгенерировать токен».

### 1. Получить документы, ожидающие переноса

```
GET /integrations/1c/api/export
Заголовок:  X-1C-Token: <токен>
(или ?token=<токен> в самом адресе)
```

Ответ:

```json
{
  "ok": true,
  "movements": [
    {
      "id": 12,
      "number": "PER-000045",
      "date": "2026-09-05T10:00:00",
      "from_warehouse": "Основной склад",
      "to_warehouse": "Товары в пути ФФ КАЗАНЬ, Взлётная 30",
      "comment": "WMS: PER-000045 (склад получатель: ОЗОН: Казань)",
      "lines": [{"barcode": "4600000000015", "name": "Свитер", "qty": 5.0}]
    }
  ],
  "inventories": [
    {
      "id": 3,
      "number": "INV-000012",
      "date": "2026-09-04T18:30:00",
      "warehouse": "Основной склад",
      "comment": "WMS: INV-000012",
      "lines": [{"barcode": "4600000000015", "name": "Свитер", "qty": 12.0}]
    }
  ],
  "supplier_returns": [
    {
      "id": 7,
      "invoice_number": "НАКЛ-001234",
      "order_number": "Ш-00105",
      "supplier": "ИП Иванов",
      "supplier_inn": "770123456789",
      "warehouse": "Основной склад",
      "comment": "WMS: возврат по приемке НАКЛ-001234",
      "lines": [{"barcode": "4600000000015", "name": "Свитер", "qty": 2.0}]
    }
  ]
}
```

Сопоставление товара — **по штрихкоду** (`barcode`), с фолбэком на точное
совпадение по `name`, если штрихкод не нашелся. Артикул в этом обмене не
участвует.

### 2. Подтвердить, что документы созданы в 1С

```
POST /integrations/1c/api/export/confirm
Заголовок:  X-1C-Token: <токен>
Тело (JSON): {
  "movement_ids": [12],
  "inventory_ids": [3],
  "supplier_return_ids": [7],
  "movement_warnings": {"12": "строка 3 не сопоставлена (barcode=\"...\"), пропущена"}
}
```

Это **id из ответа export** (для `supplier_return_ids` — id приемки в
WMS, см. выше), не номера документов. После подтверждения эти документы
больше не попадут в `export`.

`movement_warnings` — необязательное поле: id перемещения (строкой) → текст
того, что пошло не так при его создании в 1С, но не помешало создать сам
документ. Единственный источник таких предупреждений сейчас — несовпавшая
номенклатура: если строка перемещения не нашлась в 1С ни по штрихкоду, ни
по точному названию, эта строка пропускается (а не валит весь документ,
как было раньше), и в `movement_warnings` попадает, что именно пропущено.
WMS сохраняет текст в `MovementDocument.sync_warning` и показывает "⚠️"
рядом с номером документа в списке перемещений и полным текстом на
странице документа — сигнал бухгалтеру проверить/дозаполнить документ в
1С вручную.

## Повторная сверка существующих документов

`GET /integrations/1c/api/reconciliation?date_from=2026-09-01&date_to=2026-09-21`
возвращает актуальный состав за указанный период:

- всех перемещений, которые WMS ранее успешно выгрузила в 1С;
- завершенных приемок, созданных загрузкой файла накладной 1С.

Обе границы периода включаются целиком. Если параметры не переданы, WMS
использует последние 30 дней — весь накопленный список при каждой проверке
не загружается.

Команда `ФормаСверитьДокументы` во внешней обработке находит перемещения
по номеру WMS в комментарии, а приемки — по номеру входящей накладной.
Сравнение выполняется по суммарному количеству каждого товара, поэтому
одинаковый SKU в нескольких коробах WMS корректно сравнивается с одной
объединенной строкой 1С. Учитываются также строки, которые есть только в
1С, и документы, которые вообще не удалось найти. Результат отправляется
через существующий `POST /integrations/1c/api/export/confirm` и полностью
обновляет отчет **«Расхождения WMS и 1С»**. Сама сверка документы и остатки
не изменяет.

## Внешняя обработка 1С:УНФ

Готового .epf-файла тут нет — собрать его может только сама 1С:Enterprise
(Конфигуратор), которой в этом окружении нет. Вместо этого — рабочий код
в двух файлах, под два разных модуля ОДНОЙ обработки (см. ниже, зачем
именно так — раздел «Автоматический запуск синхронизации по расписанию»):

- `SyncWMS_ObjectModule.bsl` — **модуль объекта**. Вся содержательная
  логика: сопоставление номенклатуры по штрихкоду, создание документов,
  сверка. Именно этот код можно вызвать не только по кнопке, но и
  программно, без открытой формы.
- `SyncWMS_FormModule.bsl` — **модуль формы**. Только четыре тонких
  обработчика кнопок — «Синхронизировать», «Сверить документы»,
  «Тестовый прогон» и «Тестовый прогон возврата» — которые вызывают
  `Объект.<Метод>(...)` из модуля объекта и показывают результат.

Создайте в Конфигураторе новую внешнюю обработку с формой:

1. Добавьте **реквизиты обработки** (не только формы — именно реквизиты
   самого объекта, вкладка «Реквизиты» в редакторе обработки, чтобы они
   были доступны и без открытой формы): `АдресWMS` (строка), `ТокенWMS`
   (строка, тип пароль).
2. Добавьте **реквизиты формы** (независимые, не связанные с объектом):
   `ДатаНачалаСверки` (дата), `ДатаОкончанияСверки` (дата) — они нужны
   только интерактивной кнопке «Сверить документы», по умолчанию
   обработка подставит последние 30 дней, перед нажатием период можно
   изменить.
3. Добавьте на форму четыре командные кнопки, вставьте код
   `SyncWMS_FormModule.bsl` в модуль формы, а `SyncWMS_ObjectModule.bsl`
   — в модуль объекта обработки (не формы!).

«Тестовый прогон возврата» отдельно от обычного «Тестового прогона»
(тот проверяет только перемещение) — у возврата поставщику больше
специфики под конкретную базу (поиск «Заказа поставщику», автоопределение
операции на РасходнойНакладной в 1С:УНФ), и полезно уметь проверять его
прямо в Конфигураторе, без реальной приемки в WMS. Перед запуском
подставьте в `ТестовыйПрогонВозвратаНаСервере` реальное название склада и
номер существующего «Заказа поставщику» (реквизит «Номер»).

### Что нужно проверить/поправить под вашу базу

Модуль написан с фолбэками на несколько вариантов стандартных имен —
но если в вашей конфигурации есть доработки, эти места стоит сверить:

1. **Штрихкод номенклатуры** (`НайтиТоварПоШтрихкоду`) — проверяет по
   очереди справочник `ШтрихкодыНоменклатуры`, регистр сведений
   `ШтрихкодыНоменклатуры` и реквизит `Номенклатура.Штрихкод`. Если у вас
   штрихкод хранится иначе (например, у товаров с характеристиками
   размер/цвет — свой штрихкод на характеристику) — донастройте эту
   функцию.
2. **Склад по названию** (`НайтиСкладПоИмени`) — ищет точное совпадение
   `Наименование` в первом найденном справочнике складов (`Склады`,
   `СтруктурныеЕдиницы`, `МестаХранения`, `Хранилища`). Названия
   `Основной склад`, `Склад №2 (Шоссейная 167)` и `Товары в пути на
   Фулфилмент` в `wms/blueprints/integration_1c.py` должны **посимвольно**
   совпадать с тем, что в 1С — включая «№», скобки и пробелы.
3. **Организация** — код берет единственную организацию из
   `Справочники.Организации` (если она у вас не одна — самую первую по
   умолчанию, либо «ТОР-ФАРМ ООО» по имени, если она есть); если
   организаций несколько и нужна конкретная — донастройте
   `НайтиОрганизациюПоУмолчанию`.
4. **Документ «Заказ поставщику»** (`НайтиИмяДокументаЗаказаПоставщику`,
   основание для возврата в 1С:УНФ) — ищет `ЗаказПоставщику`,
   `ЗаказыПоставщикам` или `ЗаказПоставщика`. Если у вас документ
   называется иначе — добавьте имя в список.
5. **Документ «Возврат поставщику»** (`НайтиИмяДокументаВозврата`) — в
   1С:УНФ это `РасходнаяНакладная` с реквизитом **«Операция»** =
   значение перечисления, чье имя/синоним содержит «возврат» и «поставщ»
   (ищется автоматически, см. `НайтиРеквизитИЗначениеОперацииВозврата`).
   Не нашли — документ все равно создается (просто как обычная
   реализация вместо возврата, с предупреждением в журнале регистрации
   `ОбменWMS`) — переключите операцию бухгалтеру вручную и проверьте,
   как называется значение в вашем перечислении. Для более старых
   конфигураций (УТ/Бухгалтерия) оставлены как вариант отдельные виды
   документа: `ВозвратТоваровПоставщику`, `ВозвратПоставщику`,
   `ВозвратТоваров`.
6. **Привязка основания.** Сначала ищется «Заказ поставщику» по
   `order_number` (см. `НайтиЗаказПоставщикуПоНомеру`, сравнение с
   реквизитом `Номер` заказа один в один) и проставляется в реквизит
   `Заказ` или `ЗаказПоставщику` документа возврата. Если заказ не
   нашелся (или в базе нет ни одного из этих реквизитов) — фолбэк на
   старую схему: документ `Поступление` (`НайтиИмяДокументаПоступления` /
   `НайтиПоступлениеПоНомеру`) по `invoice_number`, в реквизит
   «Основание». Не нашлось ничего — возврат создается без основания, для
   ручной привязки бухгалтером (с предупреждением в диагностике).
7. **Подразделение возврата** (вкладка «Дополнительно») — всегда
   «Основное подразделение» (`ИмяПодразделенияВозвратаПоставщику`), даже
   если при заполнении по поступлению подставилось другое. Ищется по
   точному наименованию в справочнике, на который ссылается реквизит
   `Подразделение` (в 1С:УНФ — «Структурные единицы»). Не нашлось — в
   журнале `ОбменWMS` предупреждение, подразделение остается как было.

Диагностика каждой синхронизации (что сопоставилось, что нет, какие
предупреждения) пишется в журнал регистрации 1С под событием `ОбменWMS`.

## Автоматический запуск синхронизации по расписанию

По умолчанию «Синхронизировать» — кнопка, которую нужно нажимать вручную.
Чтобы перенос документов WMS → 1С (movements/inventories/supplier_returns
и корректировки, ровно то же самое, что делает кнопка) запускался сам,
без участия человека, нужен доступ к Конфигуратору 1С — добавляется
обычное регламентное задание. Сверка (`СверитьДокументыНаСервере`) сюда
не входит — ее по-прежнему запускают вручную кнопкой «Сверить документы»
при необходимости, т.к. она использует форменные `ДатаНачалаСверки`/
`ДатаОкончанияСверки`, которые не имеют смысла без открытой формы.

Именно ради этого сценария код и разнесен на модуль объекта/модуль формы
(см. выше) — регламентное задание выполняется в фоне, у него нет и не
может быть открытой формы, поэтому вызвать оно способно только методы
модуля ОБЪЕКТА (и только те из них, что помечены `Экспорт`).

### 1. Сохраните обработку в файл

В Конфигураторе выгрузите готовую внешнюю обработку SyncWMS в файл
`.epf` на диск сервера 1С — например, `C:\1C_ext\SyncWMS.epf` (Windows)
или `/opt/1c_ext/SyncWMS.epf` (Linux-сервер 1С). Путь понадобится в
регламентном задании — регламентные задания могут загружать внешнюю
обработку прямо по пути к файлу, без ее регистрации в справочнике
«Дополнительные отчеты и обработки».

### 2. Заведите константы с адресом/токеном/путем

Регламентное задание выполняется без открытой формы обработки — значит,
взять `АдресWMS`/`ТокенWMS` неоткуда, кроме как из самой конфигурации.
Добавьте в Конфигураторе три константы:

- `WMS_ПутьКОбработкеSyncWMS` (строка) — путь к `.epf` из шага 1;
- `WMS_АдресСервера` (строка) — тот же адрес, что вводится в форме
  обработки (`https://ваш-домен`);
- `WMS_Токен` (строка, желательно с пометкой «конфиденциально») — токен
  из **WMS: Обмен с 1С** → «Сгенерировать токен».

Заполните их значения через 1С:Предприятие один раз (Все функции →
Константы, если пункт меню не виден — включите его в параметрах
пользователя, «Показывать команду "Все функции"»).

### 3. Добавьте общий модуль-обертку

Новый общий модуль (Конфигуратор → Общие → Общие модули), например
`ОбменWMSПоРасписанию` — свойства: **Сервер** = да, Клиент (обычное
приложение)/Клиент (управляемое приложение) = нет, ВызовСервера = нет
(он должен выполняться только на сервере):

```bsl
Процедура ВыполнитьАвтосинхронизациюСWMS() Экспорт

	ПутьКОбработке = Константы.WMS_ПутьКОбработкеSyncWMS.Получить();
	Если ПустаяСтрока(ПутьКОбработке) Тогда
		ЗаписьЖурналаРегистрации(
			"ОбменWMS", УровеньЖурналаРегистрации.Ошибка,,,
			"Автосинхронизация: не заполнена константа WMS_ПутьКОбработкеSyncWMS.");
		Возврат;
	КонецЕсли;

	Попытка
		Обработка = ВнешниеОбработки.СоздатьОбъект(ПутьКОбработке);
	Исключение
		ЗаписьЖурналаРегистрации(
			"ОбменWMS", УровеньЖурналаРегистрации.Ошибка,,,
			"Автосинхронизация: не удалось загрузить обработку по пути """
				+ ПутьКОбработке + """: " + ОписаниеОшибки());
		Возврат;
	КонецПопытки;

	Обработка.АдресWMS = Константы.WMS_АдресСервера.Получить();
	Обработка.ТокенWMS = Константы.WMS_Токен.Получить();

	Обработка.СинхронизироватьАвтоматическиНаСервере();

КонецПроцедуры
```

`СинхронизироватьАвтоматическиНаСервере` (метод модуля объекта, см.
`SyncWMS_ObjectModule.bsl`) — тот же код, что и у кнопки
«Синхронизировать», плюс гарантированная запись результата в журнал
регистрации `ОбменWMS` (интерактивная кнопка полагается на всплывающее
«Сообщить», а в фоне его читать некому).

### 4. Заведите регламентное задание

Конфигуратор → Общие → Регламентные задания → добавить:

- **Имя метода**: `ОбменWMSПоРасписанию.ВыполнитьАвтосинхронизациюСWMS`;
- **Расписание** — например, каждые 15–30 минут (интервал настраивается
  в диалоге расписания самого задания, в коде ничего задавать не нужно);
- флажок «Использовать» — включен.

### Безопасность повторных/параллельных запусков

Ручную кнопку «Синхронизировать» можно продолжать нажимать при
необходимости — регламентное задание ее не блокирует и не мешает ей:
WMS помечает документ выгруженным сразу после `export/confirm` (см.
выше), повторные обращения просто не находят уже выгруженные документы
заново, дублей не будет, даже если оба запуска пересекутся по времени.
